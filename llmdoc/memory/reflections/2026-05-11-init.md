# Post-Init Investigation Reflection

## Task
Ran 7 parallel investigators to map the Dopamine iOS jailbreak project (Liam0205 fork of opa334/Dopamine, itself built on Fugu15 by Linus Henze). Goal: produce enough understanding to bootstrap stable llmdoc documentation.

## Key Structural Insights (Non-Obvious)

1. **Three-layer build pipeline, Make-driven, NOT Xcode-driven.** The Xcode project does not orchestrate BaseBin or exploit builds. The top-level Makefile runs `pack.sh` first, then oobPCI, then `xcodebuild`. Resources (`basebin.tar`, `basebin.tc`, `oobPCI`) are pre-built artifacts referenced by Xcode via relative paths. Any contributor who opens Xcode alone will get stale artifacts.

2. **The app binary IS the exploit orchestrator.** `main.swift` re-execs itself as `Fugu15_server` (a privileged child with persona UID 0). The child process spawns oobPCI as a DriverKit driver process. This means a single binary has three execution personalities: app UI, exploit server, and CLI subcommand handler.

3. **IPC spans five distinct mechanisms** (pipes, Mach exceptions, XPC services, hooked launchd XPC, file-based vnode monitoring). Understanding which mechanism is used where is critical -- they are NOT interchangeable and each exists because the others cannot work at that stage.

4. **The `dopamine` branch is 79 commits ahead of `origin/master`** and contains 16 fork-specific features. The fork is NOT just localization; it includes significant kernel-level changes (PPLRW rewrite from magic-page to full physmap, new exec hooks, crashreporter, path mapping via bindfs).

5. **rootlesshooks is the only Theos component.** Everything else uses raw clang Makefiles. This is easy to miss and means `$THEOS` is a hard build requirement even though most of the project does not use it.

6. **forkfix links against systemhook.dylib directly** (as a linker input, not a framework). Build order is strict and the dependency is implicit -- there is no SPM or header-level declaration.

7. **fastPath certificates (arm.pfx) are committed to the repo** with password "password". These exploit CoreTrust's fast-path evaluation to sign oobPCI as a platform DriverKit binary. The certificate chain mimics Apple OIDs.

## Surprising Findings

- **No tests exist anywhere.** No unit tests, no integration tests, no lint, no pre-commit hooks. The only quality gate is "it jailbreaks successfully on device."
- **The Exe2Driver tool hides LC_MAIN by overwriting its command type to `0x13371337`** -- a detail that would be baffling without documentation.
- **SpawnDrv uses hardware breakpoints for IPC** with the oobPCI child. Magic PC values (e.g., `0x4142434404`) encode function call IDs. This is deeply non-obvious.
- **The project has 222 auto-generated release tags** (format: `auto_<timestamp>`). This is a very high release cadence.
- **launchdhook compiles sources from `../systemhook/src/`** -- shared source files across components without a shared library abstraction.
- **Secrets are injected via `sed` during CI** into Swift source. Local builds have literal placeholder strings that presumably fail gracefully.

## Recommended Doc Structure

For this project, the most useful stable docs would be:

1. **`overview/repo-shape.md`** -- Build pipeline diagram, directory layout, artifact flow. (Investigation 01 is nearly ready to promote.)
2. **`architecture/runtime.md`** -- Component diagram, IPC mechanisms, execution flow from app launch to jailbroken state. (Investigation 02 provides this.)
3. **`architecture/exploit-chain.md`** -- The five exploit stages, tool pipeline (Exe2Driver, fastPathSign, installHaxx), certificate infrastructure.
4. **`reference/build-prereqs.md`** -- ldid, trustcache, Theos, Xcode version, Procursus toolchain. Critical for onboarding.
5. **`reference/fork-features.md`** -- The 16 features unique to the Liam fork, with file locations and toggle names.
6. **`guides/local-dev-cycle.md`** -- `make all` -> `make update` -> per-component `upload.sh` hot-swap.

## Follow-up

1. Recorder should prioritize: build pipeline, runtime architecture, and build prereqs as first stable docs.
2. `libjailbreak` implementation files need a dedicated read pass -- they define the XPC protocol and PPL primitives that all other components depend on.
3. The `ellekit` integration surface (how hooks are installed at runtime) is underdocumented and matters for anyone modifying launchdhook or watchdoghook.
4. The WIP Environment Manager feature (commit `39d10cf`) has UI only, no backend -- document this as a known incomplete area.
